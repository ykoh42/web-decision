# Kev 0.6B provenance review

Reviewed 2026-11-10 against the immutable Hugging Face and GitHub revisions below. The current published catalog still pins `onnx-community/kev-0.6b-ONNX@5a827091b3d58fe4fdfc02a5a5b2ce364047d678`; the direct-TVM Q4 CPU candidate described below is not yet integrated or approved for release.

## Pinned ONNX output

- The verified [ONNX upload commit](https://huggingface.co/onnx-community/kev-0.6b-ONNX/commit/5a827091b3d58fe4fdfc02a5a5b2ce364047d678) is by Hugging Face staff account `nico-martin`, dated 2026-09-20 19:03 UTC. Its README identifies `jaredpalmer/kev-0.6b` as the source, describes q4f16 as the default, and declares Apache-2.0.
- The q4f16 graph is 3,338,522 bytes, SHA-256 `26e059ddd954efd9897772b098db10b9eeda9b873984dc1c73b32a9ce177c7c8`. Its external data is 335,357,952 bytes, SHA-256 `777335dbc052e2e02ec7591f6eefcfb29e2c28caf52075e492d226fc27e0824b`.
- The README describes 4-bit MatMulNBits weights (block size 32), a quantized embedding, an fp32 pointer head, and fp16 elsewhere in q4f16. The graph metadata reports `producer_name=pytorch` and `producer_version=2.13.0`. That embedded metadata does not identify the export script, quantizer, command, or complete toolchain.
- The target repository has two commits. The conversion commit adds the model files directly; its tree contains no export script, quantization configuration, dependency lock, or conversion provenance record. The model's Discussions API currently reports zero discussions.

## Candidate exporter, not an execution record

- The ONNX upload is dated 2026-09-20 19:03 UTC. The public [ONNX Community converter history](https://huggingface.co/spaces/onnx-community/convert-to-onnx/commits/main) has no commits between its 2026-09-03 [`a7628cef`](https://huggingface.co/spaces/onnx-community/convert-to-onnx/commit/a7628cef7df9cd4abc04ac372d86d75f9c992922) source snapshot and the next changes on 2026-10-08. That makes `a7628cef` the best public candidate for the converter code available at upload time; there is no record tying this Space revision to the ONNX upload.
- Its [pinned requirements file](https://huggingface.co/spaces/onnx-community/convert-to-onnx/resolve/a7628cef7df9cd4abc04ac372d86d75f9c992922/requirements.txt) pins `optimum==2.1.0`, `optimum-onnx==0.1.0`, `transformers==4.57.6`, and `onnx-ir==0.2.1`. It leaves `onnx`, `onnxruntime`, and `onnxconverter-common` as version ranges and selects PyTorch by Python version (`2.5.1` below Python 3.13, `>=2.9.0` on Python 3.13+). This is not an exact environment lock; the ONNX graph's self-reported PyTorch `2.13.0` does not identify which other versions were installed.
- The candidate Space describes an `optimum-cli export onnx` step and derives several quantized variants, including q4f16. Its source and requirement files do not prove that this converter run produced commit `5a827091`, which model revision was loaded, or the exact quantization invocation and environment.

## Best-supported source candidate, not an attestation

- The ONNX README names the mutable repository ID but omits its revision. The source model's latest public revision before the ONNX upload appears to be [`jaredpalmer/kev-0.6b@93994937d1f83a06c801f7469b6793ec4c29edd5`](https://huggingface.co/jaredpalmer/kev-0.6b/commit/93994937d1f83a06c801f7469b6793ec4c29edd5), a card-only change. This is inferred from public commit timestamps; the ONNX publisher did not attest to this source revision.
- Its adapter and pointer head were last changed in [`jaredpalmer/kev-0.6b@abe7110dedfd68a185839550079bcf7c26f561ac`](https://huggingface.co/jaredpalmer/kev-0.6b/commit/abe7110dedfd68a185839550079bcf7c26f561ac). At that revision the adapter is 40,419,816 bytes with SHA-256 `deaab63b61f95d628503831e8b336e1c3e334b9a42d3530d979a5149b429c492`; `head.pt` is 2,102,399 bytes with SHA-256 `ce6cd9ffc54db41c179b65a33d60973dc8280c29e886218eb3ec07dc28d6f28b`. The hashes are unchanged in the subsequent pre-conversion source snapshot. This links the public candidate checkpoint's files, not those files to the ONNX export execution.
- The pinned source [training configuration](https://huggingface.co/jaredpalmer/kev-0.6b/resolve/abe7110dedfd68a185839550079bcf7c26f561ac/training_config.json) records base revision `da87bfb608c14b7cf20ba1ce41287e8de496c0cd` and suite SHA-256 `a8f50e481b7d90b97da049e0ff6a01cee2f1ed204aed61a8265af0edbb5514d2`. At the pinned training code commit, `kev/suite.py` pins the frozen suite mirror to `jaredpalmer/kev-suites@a3318ddc1f630c5673232efacd8123a84de3f480`, and the training loader verifies the partition against the manifest. The source training data revisions and partition are therefore identified; this does not establish which checkpoint or inputs the ONNX converter used.
- The source [training provenance](https://huggingface.co/jaredpalmer/kev-0.6b/resolve/abe7110dedfd68a185839550079bcf7c26f561ac/provenance.json) records training code commit `37cb2f6155afec1054de2cc78dfd7c7dd24a956d` and PyTorch `2.8.0+cu128`; its training code hashes match that commit. This is training provenance, not ONNX conversion provenance.
- The ONNX config's `transformers_version: 4.51.0` also appears in the pinned Qwen base config, so it is inherited model metadata and cannot establish the conversion library version.

## Rights and release gate

The ONNX card declares Apache-2.0. The Kev card declares Apache-2.0 for the adapter and head; the pinned Qwen base has an Apache-2.0 license file. The Kev model repository does not include standalone `LICENSE` or `NOTICE` files, and its training card points to datasets with their own terms. Immutable source cards, API listings, license texts, training metadata, and the matching v7 suite manifest are archived under [`kev-provenance/upstream/`](kev-provenance/upstream/); the dataset metadata review is [`kev-provenance/kev-v7-training-data-snapshot.md`](kev-provenance/kev-v7-training-data-snapshot.md). The model-card declarations are documented evidence, not a complete rights determination. Dataset terms include unknown, mixed, missing, and separately governed sources and remain unresolved.

The earlier ONNX-derived candidate still lacks a publisher attestation for its exact conversion input and recipe. That uncertainty does not apply to the new direct-TVM conversion, whose source revisions, code revision, locked tool versions, and hashes are recorded below. The exact shipped artifact still requires a completed rights and notice review. `pnpm run check:model-provenance` remains fail-closed until the catalog's actual artifact and provenance record are updated and reviewed.

## Replacement route

On 2026-11-09 the user rejected contacting either publisher and directed us to convert the official Kev checkpoint ourselves. The converter pins `jaredpalmer/kev-0.6b@abe7110dedfd68a185839550079bcf7c26f561ac` (adapter and `head.pt`), `Qwen/Qwen3-0.6B-Base@da87bfb608c14b7cf20ba1ce41287e8de496c0cd`, and Kev code `37cb2f6155afec1054de2cc78dfd7c7dd24a956d`. It verifies source hashes, assembles the official LoRA-plus-pointer-head model, exports with PyTorch, and imports directly into TVM Relax. ONNX is not an intermediate or conversion input; the pinned ONNX Q4 asset is used only as a comparison reference.

The old `scripts/build_tvm_q4.py` preview builder still imports helpers that replace private ONNX frontend methods. The new direct converter does not use those helpers. Do not extend that legacy path; retire it with the old catalog artifact after the direct model passes packaging, browser, offline, and quality gates.

The direct Relax graph has 511 weight inputs, while the bundled ONNX artifact and loader manifest describe 394. A new r4 candidate now emits the direct TVM WebGPU module, tensor cache, and three weight shards; its build report and static package metadata are pinned in [`direct-tvm-q4-webgpu-build-r4.json`](../tools/kev-converter/reports/direct-tvm-q4-webgpu-build-r4.json). This candidate is still outside the public catalog and has not been published as a package asset. The old 394-weight source map cannot be reused.

The local r4 package contains 10 payload files totaling 348,752,129 bytes, plus its 2,548-byte manifest. Every payload file currently in `.toolchains/kev-webgpu-rebuild-2026-11-11/browser-package` matches the size and SHA-256 in that manifest, with no missing or extra files. The distribution target is a public Hugging Face model repository pinned to an immutable commit. The library will map the curated model ID to that fixed internal root; callers will not provide an asset URL. No host repository, commit, or runtime root is configured, and the files have not been uploaded. This target does not clear the model's hardware or rights gates.

The direct converter pins the official `apache-tvm==0.27.0.post1` wheel in `tools/kev-converter/uv.lock`; it does not clone or modify TVM source or apply a TVM source patch. Q4 replacement uses TVM's Relax and TIRX APIs. It quantized 196 linear weights and one embedding, replacing all 196 MatMuls and the embedding Gather. The export retains an unbounded symbolic sequence dimension (`1..int_oo`), and Relax returns `[1, s53]`. The 22-token CPU comparison passed against the pinned ONNX Community Q4 reference: max logit delta `0.03369` (limit `0.15`), probability delta `0.000114` (limit `0.001`), with the selected option matching both that reference and the official FP32 source. The max logit/probability deltas from official FP32 were `0.46454` and `0.002406`; this fixture does not establish accuracy across the supported domain. The [CPU build report](../tools/kev-converter/reports/direct-tvm-q4-cpu-r12.json) has SHA-256 `29dd122974c8220be889acaa3cb05a2be39facafc83b3cdd8e12c0c831bee8e6` and includes exact input, fixture, converter, and reference hashes. The earlier r11 report remains historical.

Separately, the patch-free TIRX row-attention prototype generated 6,255-byte WGSL with a 128-thread workgroup and 2,304 bytes of workgroup storage. A synthetic WebGPU probe in Chrome 157 passed lengths 7, 17, 33, and 8,192 against a dense FP32 reference; the largest reported error was `7.92e-9`, and the 8,192-token dispatch-plus-readback measured `25.7 ms`. This covers one query/head row only; it is not full-model quality, runtime integration, exact PyTorch FP16 rounding, or GQA evidence. The [synthetic GPU report](../tools/kev-converter/reports/kev-tiled-row-webgpu-synthetic-r1.json) records the shader hash, limits, measurements, and scope.

On Chrome 157 with Intel Gen-12LP, the r4 package passed four online decision cases (22, 57, 64, and 243 tokens) with no quality issues. The 8,192-token inference started but did not complete; the over-limit rejection and offline-cache checks have not run. Dynamic inference through the full native limits, offline reuse, exact-package integration, broader numerical coverage, and dataset-rights review remain open. The catalog still selects the older ONNX-derived artifact, so this direct candidate is not available by model ID and is not approved for release.
