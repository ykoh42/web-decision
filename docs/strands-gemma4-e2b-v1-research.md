## Serving contract

- State and instructions accept text or structured JSON. The E2B v1 backend rejects image inputs. Choice takes 2–255 named options, noul returns the probability of true, and score takes an ordered rubric of 2–10 levels. The source returns named answers with choice probabilities and confidence, or the score's ordinal value, legend, probabilities, and confidence. [Request and response schema](https://github.com/strands-labs/strands-decider/blob/6d85079caf1f1906ebb0f1370b56ef28ba7aa93e/src/strands_decider/schema.py) · [Text-only engine](https://github.com/strands-labs/strands-decider/blob/6d85079caf1f1906ebb0f1370b56ef28ba7aa93e/src/strands_decider/infer.py)
- The v1 serving config rejects requests when the encoded state plus the longest question exceeds 4,096 tokens. It inserts BOS on the state. The current upstream `serve --max-length` option is restricted to v2. The model card separately reports a 32,768-token benchmark and the base text configuration has a 131,072-token positional limit. [Pinned checkpoint config](https://huggingface.co/StrandsAgents/strands-decider-E2B-gemma4-v1-2610/blob/d383ecf8534b13d49b3b567a1b66f88fca6d50ba/strands_decider_config.json) · [Prompt packing](https://github.com/strands-labs/strands-decider/blob/6d85079caf1f1906ebb0f1370b56ef28ba7aa93e/src/strands_decider/prompting.py) · [Serving flags](https://github.com/strands-labs/strands-decider/blob/6d85079caf1f1906ebb0f1370b56ef28ba7aa93e/src/strands_decider/cli.py) · [Model card](https://huggingface.co/StrandsAgents/strands-decider-E2B-gemma4-v1-2610/blob/d383ecf8534b13d49b3b567a1b66f88fca6d50ba/README.md)
- The base text decoder has 35 causal layers, with 28 sliding-window layers at 512 tokens and seven full-attention layers. The original loader attaches rank-48, alpha-96 LoRA and preserves the pointer head in FP32. The head compares the answer-position state with each option's last-token state. The checkpoint supplies per-type temperatures and ordinal smoothing. ## Existing implementation and verified work

At web-decision `ef24162`, the v1 path is an experimental FP16 adapter. Its contract already pins the stable HF tag, base revision and 4,096-token limit. It recomputes each question row, accepts more than the official 255 options, requires an app-hosted 82-shard FP16 cache and disables offline cache reuse. The loader uses TVM-internal WebGPU upload methods. The public v2 path has a separate bidirectional-state decoder and a fixed token-readout head. [Experimental contract](../packages/web-decision/src/strands/gemma4-e2b-contract.mts) · [Experimental loader](../packages/web-decision/src/strands/gemma4-e2b-loader.mts) · [Experimental protocol](../packages/web-decision/src/strands/gemma4-protocol.mts) · [Public v2 scorer](../packages/web-decision/src/strands/gemma4-v2-scoring.mts)

The new [pointer-head importer](../scripts/strands/gemma4_v1/pointer_head_ir.py) verifies the exact 9,456,104-byte head before loading it. It directly imports the official FP32 PyTorch pointer into the existing pinned TVM Relax compiler. With controlled hidden states, CPU LLVM execution matched the original selected option for 2, 3, 8 and 255 choices. TVM also compiled the WebGPU/WASM target on CPU. The [test](../scripts/strands/gemma4_v1/test_pointer_head_ir.py) covers the wrong-hash case, numeric parity and dynamic option counts.

Two valid prompts containing rare Unicode characters reproduced an offset error in the experimental protocol. The original Rust tokenizer assigns the same source span to every UTF-8 fallback byte of a character. Grouping those bytes in the browser tokenizer preserves the last-token index of each option. Five CPU differential cases using the actual pinned tokenizer now match the upstream text, token IDs and pointer indices exactly. [Protocol regression](../packages/web-decision/test/strands-gemma4-protocol.test.mts)

## Causal layer 0

The [causal layer importer](../scripts/strands/gemma4_v1/causal_layer_ir.py) checks the original base and adapter files against their SHA-256 pins before loading one layer. It exports the pinned Hugging Face eager causal layer with the original unmerged PEFT adapter active. The model-side [BF16 lowering](../scripts/strands/gemma4_v1/bf16_lowering.py) follows the v2 convention of keeping the stored BF16 bits in pairs of 16-bit words carried by a `uint32`. It keeps the FP32 LoRA tensors intact. The exported graph determines each BF16 rounding boundary, including the base projection and the cast after adding the FP32 LoRA branch. TVM receives external parameters and lowers the bit operations through its supported Relax import and tensor-expression APIs.

The [layer tests](../scripts/strands/gemma4_v1/test_causal_layer_ir.py) verify exact stored bytes for 17 BF16 tensors and 14 FP32 LoRA tensors. They compare the TVM LLVM output with the original BF16 layer using upstream RoPE and the sliding causal mask. Deterministic activations at 2, 8, 37 and 513 tokens had maximum absolute differences of 0.015625, 0.0234375, 0.0625 and 0.09375. A 69-token request using the pinned tokenizer, word embedding and PLE weights had maximum difference 0.125 and mean difference 0.00027846. Causal and sliding-window perturbations left the masked outputs exactly equal. The same graph compiles to the WebGPU/WASM target on CPU. These measurements describe layer activations. The model has no release tolerance for these comparisons.

## KV families and bounded attention

Layers 0–14 own their KV projections. Sliding layer 13 and full-attention layer 14 also produce the shared K/V for layers 15–34. Shared layers use five FP32 LoRA pairs, and the other layers use seven. The tests import an independent full-attention layer 4, send the compiled K/V from layer 13 to layer 15 and from layer 14 to layer 19, and compile each representative for WebGPU/WASM on CPU. At eight tokens, the maximum absolute hidden-state differences from the original CPU layers for indices 4, 13, 14, 15 and 19 were 0.03125, 0.0625, 0.0625, 0.125 and 0.15625, respectively.

For a 4,032-token prefix and 64-token continuation, the original sliding cache retained 511 keys and returned 575 visible keys starting at absolute position 3,521. Its full-attention counterpart returned all 4,096 keys from position zero. Compact BF16 prefix K/V for the 12 sliding and three full-attention owner layers needs at most 31,444,992 bytes. This accounts for both K/V tensors and allows the full context for every full-attention owner. Transient buffers and the runtime allocation peak require separate measurements. [Pinned decoder configuration](https://huggingface.co/google/gemma-4-E2B-it/blob/3e22461f65e89153144f8adb70e3b8c2cc9845a7/config.json) · [Transformers cache implementation](https://github.com/huggingface/transformers/blob/v5.22.2/src/transformers/cache_utils.py)

The standalone [attention tile importer](../scripts/strands/gemma4_v1/causal_attention_ir.py) keeps the original BF16 score and probability rounding around the FP32 softmax. It bounds one score tensor at 8 MiB for 64 query rows against 4,096 keys, down from 512 MiB in the dense layer. A tile mask is 1 MiB at that shape. Repeated K and V can each reach 64 MiB for a full-attention layer if materialized. The [attention tests](../scripts/strands/gemma4_v1/test_causal_attention_ir.py) exercise the 64-plus-one query boundary for both head widths, a single query against 4,096 keys, and exact invariance to perturbing a future value. The standalone tile has CPU differential measurements and WebGPU/WASM code generation.

## Tiled layer and continuation

The [tiled layer](../scripts/strands/gemma4_v1/tiled_causal_layer.py) invokes three native TVM graphs for Q/K/V projection, attention and the output projection plus feed-forward tail. The CPU runner widens active BF16 K/V once per call and reuses them across query tiles. It builds each causal mask from the absolute query and key positions and runs the tail on the same 64-row slices. A sliding owner returns a compact BF16 prefix of at most 511 rows. A shared producer also returns its active K/V for consumers in that call. The owner keeps its prefix available for multiple continuations.

The [integrated tests](../scripts/strands/gemma4_v1/test_tiled_causal_layer.py) compare the masks with the original eager `DynamicCache`, including an absolute position beyond the 512-token sliding window. They also exercise the actual layer 0 weights with a 69-token request as a whole, as state and question, and with a single final token. Whole-request and question-continuation maximum activation differences were 0.125, with means 0.00027846 and 0.00032517. The single-token continuation had maximum difference 0.01171875. Reusing the same prefix gave identical outputs with unchanged K/V. The continuation tests also pass live tiled K/V from the pinned producer 13 to consumer 15 and from producer 14 to consumer 19. All three layer 0 graph stages compile to the WebGPU/WASM target on CPU.

## Complete decoder on CPU

The [tiled decoder](../scripts/strands/gemma4_v1/tiled_causal_decoder.py) connects all 35 pinned layers and the final RMS normalization through native TVM graphs. Its Python CPU runner reads the requested word and PLE embedding rows, projects the PLE for every layer, and passes each layer its own prefix. Layer 13 supplies the 16 sliding-window consumers. Layer 14 supplies layers 19, 24, 29 and 34. Those shared layers consume the live K/V from their producer on each call. The reusable result retains BF16 K/V only for the 15 owners.

The [full decoder test](../scripts/strands/gemma4_v1/test_tiled_causal_decoder.py) runs the official Strands loader with the pinned local assets, CPU BF16 eager attention and FP32 pointer head. It compares a 20-token state and 49-token choice question through the whole decoder and through a reused prefix. It checks exact word and PLE embeddings, the complete owner/consumer map, and unchanged prefix K/V after branching. It also compiles the original FP32 pointer head to native TVM and compares its logits using the options' upstream token positions.

The initial Apple M4 Pro run used TVM's serial FP32 mean in RMSNorm. Its whole-prompt maximum and mean absolute differences in final hidden states were 10 and 0.02672255. The state prefix had differences of 10 and 0.02897847, and the continuation had differences of 8 and 0.02580177. In both execution modes the original pointer logits were `[0.84082258, -0.84773129]` and the TVM logits were `[0.83748358, -0.84596533]`. The original and TVM chose the same option for this input.

An all-layer trace on the 20-token prefix found the first differences at layer 0 and the first larger increase at layer 3. With identical BF16 activations at the RMSNorm boundary, the layer 0 and 3 feeds to the MLP differed in 11 and five BF16 outputs. With original Q/K/V, their attention outputs differed in one and zero values. The largest pre-normalization difference at the final decoder layer was 0.75. After the learned final RMSNorm, the largest output difference was 10, from 187 to 197 at token 1 and hidden position 65.

The model-specific lowering now sums squared FP32 inputs in 32-column blocks before the final mean. The two isolated MLP input norms and the final RMSNorm on the original final-layer input matched the source exactly in the trace. The accumulated maximum and mean differences at the end of the 20-token prefix decreased to 6 and 0.02589779. Isolated BF16 projection comparisons still showed rounding differences in the base dot products even when both paths used the same FP32 LoRA update.

The revised CPU run had maximum and mean final hidden-state differences of 8 and 0.02634349 for the whole prompt, and 8 and 0.02652541 for the continuation. It returned pointer logits `[0.84181780, -0.82621145]` in both modes and chose the same option as the original. The maximum pointer logit difference increased from 0.00333899 to 0.02151984. These measurements describe one CPU input with Strands Decider `13c0514`, PyTorch 2.8.0, Transformers 5.22.2, PEFT 0.21.0 and TVM 0.27.0.post1. The numerical release criterion is still open.

Public support requires a browser runner over the complete graph, pinned online and offline asset loading, independent WASM builds, exact-package browser inference, cleanup, failure handling and measured hardware limits.

## Private package and CPU ABI replay

The private E2B v1 path joins four pinned causal layer families into one native WebGPU/WASM module. Thirteen entry points cover Q/K/V projection, causal attention, the residual and feed-forward tail, per-layer embedding projection, final normalization and the FP32 pointer. The build verifies the representative graph parameters against the original stored BF16 and FP32 bytes and checks every layer's bindings. [Native builder](../scripts/strands/gemma4_v1/build_model.py)

The private browser decoder defaults to the checkpoint's 4,096-token serving window and accepts an explicit window up to the pinned 131,072-position capacity. It supports 255 choice options and ten score levels. The pinned E2B v1 image loader refuses Gemma4. The browser defaults to one causal state prefix per upstream request batch of multiple questions. Users can set the original question batch size and padded-token budget or disable prefix reuse, with usage reflecting the evaluations. Two independently pinned sources support hashed range reads and offline reuse after both inventories have been prepared. [Runtime](../packages/web-decision/src/strands/gemma4-v1-runtime.mts) · [Pinned prompt policy](https://github.com/strands-labs/strands-decider/blob/6d85079caf1f1906ebb0f1370b56ef28ba7aa93e/src/strands_decider/prompting.py)

The separate CPU-WASM build uses the same graph ABI and TypeScript decoder. A four-token real-checkpoint comparison opened 1,677 verified local ranges and returned logits [1.39015329, 1.19158113]. The pinned BF16 torso and original FP32 head returned [1.39806342, 1.18674743]. Both selected the same slot. The six existing typed-question fixtures also matched the original token IDs, pointer positions and rounded API answers calculated from the original logits.

The single-head K/V graph was compiled for WebGPU, and its isolated CPU attention path ran one query against 131,072 keys. This is evidence for the allocator and kernel boundary. Full-window inference, device limits, throughput, and release thresholds require results from the exact package. The package retains the model license and TVM notices. It is private.
