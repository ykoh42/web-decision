# Experimental Kev q2-k128 candidate provenance

Status: this is the provenance record for the unpublished experimental npm package `web-decision@0.4.0-next.0`, which registers the explicit ID `experimental-kev-0.6b-q4f16-upstream`. It is not a release asset. The package keeps the released `kev-0.6b-q4f16` route and pins intact, adds no automatic model default or public model URL, and is not published. The package bundles a candidate q2-k128 TVM WASM and metadata; at runtime it reconstructs the nine verified shards from the pinned upstream ONNX external-data file. A separate 14-file asset pack and its packager were prepared only as local review artifacts; that pack is not the ID-only runtime distribution.

## Verification evidence

- Native Windows Node 22.23.1 / headless Chrome 156.0.8078.81 loaded this manifest on Intel `gen-12lp` WebGPU with default Chrome flags, `shader-f16`, and adequate reported limits. The previous candidate run returned a finite result for one 30-token request; this is a smoke test, not a quality test.
- The exact 74-token 0.3 Chromium fixture was replayed. Against the recorded Apple M4 Pro run, the candidate differed by at most 0.00977 in logits and 0.00319 in probabilities; typed rounded probabilities differed by at most 0.0032 and the score by 0.0044. This is one fixture on different GPU vendors.
- Seven candidate cases (40 option scores) were compared with the pinned raw ONNX graph on ONNX Runtime 1.31.1 CPU. The two archived fixture token arrays matched 0.3 `packedInputs` exactly. Max/mean absolute logit differences were 0.17090 / 0.05525; max/mean probability differences were 0.02432 / 0.00554. These cross-device/backend results have no accepted tolerance and do not prove equivalence.
- Option-order outputs changed on both candidate and raw ONNX CPU runs; the maximum mapped probability drift was 0.30388 and 0.29184 respectively. This is descriptive evidence; no order-invariance acceptance threshold is asserted. Full per-option results and input IDs are retained only in the local review checkout at `work/windows-test/web-decision-src/next/kev-assets/verification/`; they are not part of this npm package.

## Notices and distribution limits

- `notices/` contains the Qwen Apache-2.0 license, Emscripten/musl/libc++/compiler-rt notices, TVM/TVM-FFI/DLPack notices, and this candidate provenance file. `NOTICE-SOURCES.md` records origins and hashes. These records are not legal clearance.
- The Qwen license is the official `Qwen/Qwen3-0.6B-Base` `LICENSE` from revision `da87bfb608c14b7cf20ba1ce41287e8de496c0cd`, SHA-256 `832dd9e00a68dd83b3c3fb9f5588dad7dcf337a0db50f7d9483f310cd292e92e`. The model cards report Apache-2.0 for the Kev adapter/head and Qwen3 base; training-data terms and redistribution approval were not reviewed here.
- The separate asset-pack tool remains candidate-specific and imports the existing 0.3 `prepareAssetPack` validator, but its pins are separate. It requires an explicit trusted scratch parent outside the checkout, creates a unique output directory there, and returns that directory. It verifies POSIX owner-only mode bits and fails closed when the filesystem does not preserve them. Windows callers must supply a parent with a trusted ACL because this Node implementation cannot inspect or set Windows ACLs. The npm package does register the explicit experimental model ID, but no default model, public URL, or publication step is configured.
- The prepared pack was run with native Windows Node 22.23.1 and its output was independently checked against every manifest and notice byte count/SHA-256. The run produced 14 inference assets (349,096,401 bytes), 14 notice files (131,369 bytes), and no extra files. The updated packager tests pass all 10 subtests, including two simultaneous successful preparations under one parent. The detailed log is retained only in the local review checkout at `work/windows-test/web-decision-src/next/kev-assets/verification/packager-verification.json`; it is not part of this npm package.
- The 0.3 validator still checks for an existing destination before staging, then renames the staged directory. The candidate wrapper creates a unique output destination inside a private POSIX `0700` directory and verifies its mode, preventing other users from reaching that destination when the scratch parent is trusted. Same-UID processes remain in the trust boundary. On Windows, use a parent protected by an ACL that excludes untrusted users; the wrapper does not inspect ACLs.
- The q2 build-fixes patch is kept as a separate review artifact. The official 0.3 WASM/manifest pins remain intact. The release gate still requires redistribution/legal review and an explicit decision about observed numerical differences.
