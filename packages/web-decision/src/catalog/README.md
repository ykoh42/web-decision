# Model catalog

model-spec.json is the manually curated source for model IDs, adapters, public
descriptions, and capabilities. It deliberately contains no artifact hashes.

artifacts.lock.json is generated by
packages/web-decision/scripts/build-model-catalog.mjs from the spec and the
checked-in Kev manifest, bundled runtime files, pinned upstream contract, and
shard map. It stores per-model pins under byModelId. index.generated.js and its
declaration files are generated from the same inputs. Run the script to update
them, or pass --check to confirm the generated files are current.

The catalog has one entry for kev-0.6b-q4f16 on the kev06 adapter. Its TVM
WebAssembly and small metadata files are bundled. Model tensor data is fetched
from the pinned upstream ONNX external-data file and reconstructed into shards;
the catalog does not describe a hosted native TVM model pack.

The pinned manifest currently has experimental=true. The artifact lock
preserves that source fact and does not infer a release state from it. The
previous M4 Pro report is historical evidence for preview.34; it is not an
input to the artifact lock or a claim about the current bundle. Generated
metadata marks current bundle GPU verification as not-revalidated. Artifact
hash checks and hardware release validation are separate gates.

To add another model, append a unique modelId and a TVM WebGPU description to
model-spec.json, then add an adapter-specific recipe to
build-model-catalog.mjs that validates that model's artifacts. Update the
generated description types if the new adapter has different metadata. Unknown
adapters and non-TVM backends fail closed. Regenerate the lock, catalog, and
types, then add source-integrity and capability assertions for the new model.
